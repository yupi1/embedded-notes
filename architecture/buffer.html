Буфер (Buffer)

Буфер — тимчасова область пам'яті між відправником і приймачем. Він вирівнює різницю в швидкості обробки даних і дозволяє системам працювати асинхронно, не чекаючи одна на одну.

01 — Що таке буфер

Буфер як черга між двома пристроями

Коли передавач надсилає дані швидше, ніж приймач може їх обробити — без буфера дані втрачаються. Буфер «ловить» байти, що надходять, і зберігає їх до моменту, коли приймач буде готовий прочитати.

В мікроконтролерах буфери є скрізь: UART RX/TX буфери, DMA буфери, SPI FIFO, USB endpoint буфери. Принцип один — акумуляція → поріг → обробка.

KEY
Ключова ідея: Буфер — це не просто пам'ять. Це угода між двома сторонами: відправник пише коли хоче, приймач читає коли готовий. Буфер посередині гарантує, що нічого не загубиться.
INF
Аналогія: Поштова скринька перед дверима. Листоноша кидає листи коли прийшов — ти читаєш коли зручно. Скринька — буфер між вами двома.
02 — Інтерактивна анімація

03 — Принцип роботи

Як буфер реалізується насправді

Найпоширеніша реалізація буфера в embedded — кільцевий буфер (Ring Buffer / Circular Buffer). Два вказівники: head (куди пишемо) і tail (звідки читаємо). Буфер фіксованого розміру, вказівники рухаються по колу — звідси і назва.

Компонент Роль В коді (STM32)
TX Buffer Накопичує дані для відправки. DMA/IRQ передає по одному байту. HAL_UART_Transmit_DMA()
RX Buffer Приймає байти з UART. Коли досягнуто поріг — IRQ будить задачу. HAL_UART_Receive_IT()
Поріг (X) Кількість байт, після якої відбувається flush. Типово: розмір пакету або таймаут. RXNE_THRESHOLD
Flush Атомарна операція: зчитати весь буфер, скинути лічильник, передати у чергу задач. osMessageQueuePut()
WRN
Buffer Overflow! Якщо приймач не встигає зчитувати, а буфер заповниться повністю — нові байти губляться. Вирішення: збільшити буфер, підвищити пріоритет задачі, або додати flow control (XOFF/CTS).
04 — Код

Реалізація Ring Buffer та Flush-логіки

Мінімальна реалізація кільцевого буфера з порогом для STM32 + FreeRTOS.

/* ── Визначення Ring Buffer ────────────────────────────────── */
#define RX_BUF_SIZE  64
#define FLUSH_THRESHOLD 8   /* поріг X: flush при N байтах */

typedef struct {
    uint8_t  data[RX_BUF_SIZE];
    uint16_t head;   /* вказівник запису  */
    uint16_t tail;   /* вказівник читання */
    uint16_t count;  /* кількість байт в буфері */
} RingBuf_t;

static RingBuf_t rxBuf = {0};

/* ── UART RX IRQ — кожен байт, що прийшов ─────────────────── */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (rxBuf.count < RX_BUF_SIZE) {
        rxBuf.data[rxBuf.head] = rxByte;        /* покласти в буфер */
        rxBuf.head = (rxBuf.head + 1) % RX_BUF_SIZE; /* просунути head */
        rxBuf.count++;
    } else {
        overflowCount++;                        /* буфер повний — overflow! */
    }

    /* Поріг досягнуто — будимо задачу обробки */
    if (rxBuf.count >= FLUSH_THRESHOLD) {
        BaseType_t xHigherPriorityTaskWoken = pdFALSE;
        vTaskNotifyGiveFromISR(rxTaskHandle, &xHigherPriorityTaskWoken);
        portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
    }
    HAL_UART_Receive_IT(&huart1, &rxByte, 1); /* наступний байт */
}

/* ── FreeRTOS задача: flush буфера ─────────────────────────── */
void RxProcessTask(void *arg) {
    uint8_t packet[RX_BUF_SIZE];
    uint16_t len;

    for (;;) {
        ulTaskNotifyTake(pdTRUE, portMAX_DELAY); /* чекаємо сигналу */

        /* ── FLUSH: читаємо весь буфер атомарно ── */
        taskENTER_CRITICAL();
        len = rxBuf.count;
        for (uint16_t i = 0; i < len; i++) {
            packet[i] = rxBuf.data[rxBuf.tail];
            rxBuf.tail = (rxBuf.tail + 1) % RX_BUF_SIZE;
        }
        rxBuf.count = 0;           /* буфер порожній */
        taskEXIT_CRITICAL();

        /* Передаємо пакет черзі задач (черга FreeRTOS) */
        osMessageQueuePut(msgQueue, packet, 0, 0);
    }
}
Q&A — Питання на співбесіді
Чому буфер кільцевий, а не лінійний масив? ▾

Лінійний масив вимагав би зсуву всіх елементів при кожному читанні — O(n) операцій, що критично в ISR. Кільцевий буфер пересуває лише вказівник tail — O(1). Жодної пам'яті не переміщується, жодного копіювання. Це і є причина повсюдного використання в embedded.

Що таке buffer overflow і як захиститись? ▾

Buffer overflow — ситуація, коли дані надходять швидше, ніж буфер може прийняти. Нові байти перезаписують старі або губляться.

Захист: 1) збільшити розмір буфера, 2) підвищити пріоритет задачі-обробника, 3) hardware flow control (RTS/CTS для UART), 4) програмний flow control (XON/XOFF), 5) DMA з double buffering — поки одна половина обробляється, в другу йдуть нові дані.

Як flush відбувається без втрати даних з IRQ? ▾

Flush виконується в критичній секції (taskENTER_CRITICAL) або з вимкненими перериваннями. За час flush IRQ не може модифікувати head або count. Після flush count = 0 і tail = head, IRQ знову може писати — без race condition.

Чому не флашити побайтово, а ждати порогу? ▾

Кожна обробка пакету — це overhead: перемикання контексту FreeRTOS, виклик callback, можливо перевірка CRC. Якщо обробляти кожен байт окремо — overhead може перевищити корисну роботу. Групова обробка (flush by threshold) амортизує витрати: один виклик обробника — N байт. Типовий поріг = розмір протокольного пакету.
