01 — Визначення

CAN (Controller Area Network) — це диференціальна послідовна шина з підтримкою кількох вузлів (multi-master), яка не потребує центрального хоста (мастера). Кожен вузол може надсилати повідомлення на шину будь-коли. Якщо два вузли намагаються говорити одночасно — апаратний арбітраж вирішує хто перемагає без колізій та втрати даних.

KEY
Головна ідея: CAN передає не адресу одержувача, а ідентифікатор повідомлення. Всі вузли чують все — кожен сам вирішує, чи потрібне йому це повідомлення, на основі ID. Це схоже на радіомовлення: один говорить, всі слухають, кожен бере своє.
02 — Фізичний рівень

CAN використовує диференціальну пару CAN_H та CAN_L. Різниця напруг між ними визначає логічний стан шини. Це забезпечує стійкість до електромагнітних завад (EMI) — обидва дроти однаково наводяться шумом, але різниця між ними залишається незмінною.

CAN_H
CAN High
У домінантному стані (0) — підтягується до ~3.5V. У рецесивному (1) — ~2.5V (шина у спокої). Підключається до CAN_H усіх вузлів паралельно.
CAN_L
CAN Low
У домінантному стані — опускається до ~1.5V. У рецесивному — ~2.5V. Різниця CAN_H − CAN_L: домінантний = 2V, рецесивний = 0V.
120Ω
Термінальні резистори
На обох кінцях шини ставляться резистори 120 Ом між CAN_H і CAN_L. Вони поглинають відбиття сигналу і є обов'язковими. Відсутність — часта причина нестабільної роботи.
GND
Спільна земля
Хоча CAN диференціальний — всі вузли мають мати спільну опорну землю. Без неї диференціальний приймач може вийти за допустимий діапазон вхідних напруг.
WRN
Критично: Без термінальних резисторів на кінцях шини — сигнал відбивається і шина нестабільна. Особливо помітно на швидкостях вище 125 кбіт/с. Перевіряй мультиметром: між CAN_H і CAN_L має бути ~60 Ом (два по 120 паралельно).

04 — Data Frame — структура кадру

Основний тип повідомлення CAN — Data Frame. Він складається з полів з чітко визначеними розмірами та функціями. Стандартний CAN має 11-бітний ID (CAN 2.0A), розширений — 29-бітний (CAN 2.0B).

CAN Data Frame — Standard (11-bit ID, CAN 2.0A)
SOF ID DATA CRC+ACK
ПолеРозмірПризначення
SOF 1 bit Start of Frame — домінантний біт (0), що синхронізує всі вузли на шині.
ID (Arbitration) 11/29 bit Ідентифікатор повідомлення, а не адреса вузла. Менший числовий ID = вищий пріоритет. Визначає хто виграє арбітраж.
RTR 1 bit Remote Transmission Request. 0 = Data Frame (є дані). 1 = Remote Frame (запит даних у вузла).
DLC 4 bit Data Length Code — кількість байт даних (0–8 для CAN, 0–64 для CAN FD).
DATA 0–8 байт Корисне навантаження. Вміст визначається протоколом вищого рівня (CANopen, J1939, UDS).
CRC 15 bit Cyclic Redundancy Check — виявляє помилки у передачі. Якщо не збігається — генерується Error Frame.
ACK 2 bit Підтвердження. Будь-який вузол, що успішно прийняв CRC, тягне шину домінантною — підтверджує доставку. Відправник перевіряє це поле.
EOF + IFS 7 + 3 bit End of Frame — 7 рецесивних біт закінчення. IFS (Inter-Frame Space) — мінімальна пауза між фреймами.
05 — Арбітраж без деструкції

CAN вирішує колізії через побітовий арбітраж — CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance). Кожен вузол, поки передає, одночасно читає шину. Якщо він надіслав рецесивний біт (1), але прочитав домінантний (0) — хтось інший перемагає, і вузол миттєво зупиняється без помилки і спробує пізніше. Переможець навіть не знає що відбувся арбітраж.

Побітовий арбітраж — ECU·2 (0x080) перемагає ECU·1 (0x100) CSMA/CA
KEY
Правило домінування: На CAN шині домінантний стан (0) завжди перекриває рецесивний (1). Як і в фізиці: якщо хоча б один вузол тягне шину вниз — вона йде вниз, незалежно від кількості вузлів що надсилають 1. Тому менший ID виграє — він раніше надсилає домінантний біт (0).
05b — Bit Timing — анатомія одного біта

Один CAN-біт розбитий на чотири сегменти у Time Quanta (TQ). Правильне налаштування їхніх пропорцій — ключ до стабільної роботи. Точка вибірки (Sample Point) знаходиться між Seg1 та Seg2 і повинна бути в центрі стабільної частини біта.

06 — Швидкість та відстань

Існує жорсткий компроміс між baud rate і максимальною довжиною шини. Чим довша шина — тим більше часу займає поширення сигналу, і тим повільнішим має бути бод-рейт. CAN FD дозволяє прискорити лише фазу DATA — арбітраж залишається повільнішим.

CAN FD (Flexible Data-rate) — розширення стандарту 2012 р. Дозволяє до 64 байт даних у фреймі (замість 8) та підвищену швидкість у фазі даних (до 8 Мбіт/с). Фаза арбітраж залишається на звичайній швидкості для сумісності. Потребує підтримки в трансивері та контролері.
06b — CAN FD — подвійна швидкість у дії

CAN FD (ISO 11898-1:2015) дозволяє перемкнутись на вищий baud rate після фази арбітражу. Один і той же трансивер — але фаза DATA летить у 4–8 разів швидше. Нижче — анімація передачі класичного CAN проти CAN FD.

07 — Будова CAN-вузла

Кожен вузол на CAN-шині складається з трьох рівнів: мікроконтролер (логіка та протокол), CAN-контролер (апаратна обробка фреймів, фільтрація, буферизація) та CAN-трансивер (фізичний рівень, диференціальні сигнали).

КомпонентПризначення
CAN Controller
(bxCAN, FDCAN)		 Апаратно формує та розбирає фрейми, виконує арбітраж і bit-stuffing, зберігає повідомлення у TX/RX mailboxes. CPU спілкується з ним через регістри або DMA.

TJA1050, SN65HVD230		 Окрема мікросхема. Перетворює логічні рівні MCU (TX/RX 3.3V/5V) на диференціальні сигнали CAN_H/CAN_L. Забезпечує ізоляцію та захист від ESD.
ERR
Bus-Off стан: Якщо вузол реєструє занадто багато помилок (TEC > 255), він переходить у Bus-Off і повністю відключається від шини. Це захист від несправного вузла, що блокує всю мережу. Відновлення — тільки через програмний reset або 128×11 рецесивних біт на шині.
07b — Error Counters — механізм самозахисту шини

Кожен CAN-вузол незалежно веде два лічильники: TEC (Transmit Error Counter) та REC (Receive Error Counter). Вони визначають поточний стан вузла. Несправний вузол автоматично ізолюється — решта шини продовжує працювати.

08 — Переваги, недоліки та порівняння протоколів
Переваги
  • Multi-master — будь-який вузол може ініціювати передачу без центрального арбітра.
  • Детермінований пріоритет — нижчий ID гарантовано виграє арбітраж, без колізій і втрати даних.
  • Апаратна захищеність — CRC 15 біт, bit monitoring, ACK, bit stuffing. Виявляє 5 класів помилок апаратно.
  • Диференціальна пара — стійкість до EMI; не потрібен окремий дріт GND між вузлами.
  • Автоматичний повтор і ізоляція — при програшу арбітражу повторює апаратно; несправний вузол іде в Bus-Off.
  • До 127 вузлів на одній шині лише двома дротами.
Недоліки
  • Невелика корисна ємність — максимум 8 байт на фрейм (CAN FD: 64 байт). Великі дані потребують фрагментації.
  • Немає шифрування — всі вузли чують весь трафік; автентифікація вимагає протоколу вищого рівня (SecOC).
  • Трансивер обов'язковий — MCU не може підключитись напряму до шини без зовнішньої мікросхеми.
  • Складне налаштування bit timing — помилки конфігурації важко відлагоджувати без аналізатора шини.
  • Відстань vs швидкість — жорсткий компроміс, не можна мати одночасно довгу шину і високий baud rate.

// ── Ініціалізація bxCAN (STM32F1/F4) ───────────────────────── */
CAN_HandleTypeDef hcan;

void MX_CAN_Init(void) {
    hcan.Instance                  = CAN1;
    hcan.Init.Prescaler            = 4;      // 36MHz / 4 / (6+1+1) = 1 Мбіт/с
    hcan.Init.Mode                 = CAN_MODE_NORMAL;
    hcan.Init.SyncJumpWidth        = CAN_SJW_1TQ;
    hcan.Init.TimeSeg1             = CAN_BS1_6TQ;
    hcan.Init.TimeSeg2             = CAN_BS2_1TQ;
    hcan.Init.TimeTriggeredMode   = DISABLE;
    hcan.Init.AutoBusOff          = ENABLE;  // авто-відновлення з Bus-Off
    hcan.Init.AutoWakeUp           = DISABLE;
    hcan.Init.AutoRetransmission   = ENABLE;  // авто-повтор при поразці
    hcan.Init.ReceiveFifoLocked   = DISABLE;
    hcan.Init.TransmitFifoPriority = DISABLE;
    HAL_CAN_Init(&hcan);
}

// ── Налаштування фільтра ────────────────────────────────────── */
void CAN_FilterConfig(void) {
    CAN_FilterTypeDef f = {0};
    f.FilterBank           = 0;
    f.FilterMode           = CAN_FILTERMODE_IDMASK;
    f.FilterScale          = CAN_FILTERSCALE_32BIT;
    f.FilterIdHigh         = 0x0080 << 5;  // приймаємо ID 0x080
    f.FilterMaskIdHigh     = 0x07FF << 5;  // маска: всі 11 біт точно
    f.FilterIdLow          = 0x0000;
    f.FilterMaskIdLow      = 0x0000;
    f.FilterFIFOAssignment  = CAN_RX_FIFO0;
    f.FilterActivation     = ENABLE;
    HAL_CAN_ConfigFilter(&hcan, &f);
    HAL_CAN_Start(&hcan);
    HAL_CAN_ActivateNotification(&hcan, CAN_IT_RX_FIFO0_MSG_PENDING);
}

// ── Надіслати фрейм ─────────────────────────────────────────── */
void CAN_Send(uint32_t id, uint8_t *data, uint8_t len) {
    CAN_TxHeaderTypeDef hdr = {0};
    uint32_t mailbox;
    hdr.StdId  = id;
    hdr.IDE    = CAN_ID_STD;
    hdr.RTR    = CAN_RTR_DATA;
    hdr.DLC    = len;             // 0..8 байт
    HAL_CAN_AddTxMessage(&hcan, &hdr, data, &mailbox);
    // mailbox: 0/1/2 — контролер сам обирає вільний
}

// ── RX переривання ─────────────────────────────────────────── */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan) {
    CAN_RxHeaderTypeDef hdr;
    uint8_t data[8];
    HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &hdr, data);
    // hdr.StdId — ID відправника, hdr.DLC — кількість байт
    process_can_message(hdr.StdId, data, hdr.DLC);
}

// Передача
void can_send(void) {
    twai_message_t msg = {
        .identifier       = 0x080,
        .data_length_code  = 4,
        .data              = {0x01, 0x02, 0x03, 0x04},
    };

}

// Прийом (блокуючий, з timeout 100 мс)
void can_receive_task(void *arg) {
    twai_message_t msg;
    for (;;) {
        if (twai_receive(&msg, pdMS_TO_TICKS(100)) == ESP_OK) {
            process_can_message(msg.identifier, msg.data, msg.data_length_code);
        }
    }
}
10 — Питання на співбесіді

CAN — диференціальна multi-master шина. Немає master/slave топології — будь-який вузол надсилає дані коли хоче. Арбітраж апаратний, без колізій.

UART — асинхронний, лише 1:1 (точка-точка), немає механізму пріоритетів. CAN спроектований саме для мереж з кількома вузлами.

SPI — синхронний, master-slave, потребує окремого CS на кожен slave. На CAN можна підключити 127 вузлів лише двома дротами без будь-якої адресації.

Ключова відмінність CAN: передається ідентифікатор повідомлення, а не адреса отримувача. Всі чують всіх — фільтри визначають кому що потрібне.

CAN використовує CSMA/CA — побітовий арбітраж. Кожен вузол, поки надсилає, одночасно читає шину. Якщо надіслав рецесивний біт (1), але прочитав домінантний (0) — хтось інший надіслав 0, і цей хтось має нижчий ID (вищий пріоритет).

Вузол з вищим ID миттєво припиняє передачу і переходить в режим прийому, не генеруючи Error Frame. Переможець навіть не знає про конкуренцію і завершує свій фрейм без жодних змін.

Колізій немає, бо домінантний стан фізично перекриває рецесивний (провідне АБО на шині). Даних не губиться — переможений просто спробує ще раз пізніше.

Bit Stuffing — правило: після п'яти однакових бітів підряд автоматично вставляється один протилежний. Наприклад, після п'яти одиниць підряд — вставляється нуль.

Навіщо: CAN синхронізується по переходах сигналу. Якщо даних немає (довга послідовність однакових бітів) — вузли можуть «розійтись» в часі через кристалічний дрейф. Вставлений біт гарантує перехід і дозволяє всім вузлам синхронізуватись.

Це збільшує максимальну довжину фрейму, але є апаратною операцією — CAN-контролер сам додає і видаляє stuffed bits без участі CPU.

CAN виявляє 5 типів помилок: CRC Error (неправильна контрольна сума), Bit Error (надісланий біт ≠ зчитаному; крім арбітражу та ACK), Stuff Error (порушення правила bit stuffing), Form Error (неправильний формат кадру: SOF/EOF/ACK delimiter), ACK Error (жоден вузол не підтвердив прийом).

При виявленні помилки вузол надсилає Error Frame — 6+ домінантних бітів поспіль, що порушує stuffing і сигналізує всій мережі про помилку. Всі вузли відкидають поточний фрейм.

Кожен вузол веде TEC (Transmit Error Counter) і REC (Receive Error Counter). При TEC > 127 — вузол переходить у Error Passive (менш агресивні Error Frames). При TEC > 255 — Bus-Off, повне відключення від шини.

CAN шина — довга лінія передачі. Коли сигнал доходить до кінця ненавантаженої лінії, він відбивається і повертається назад, накладаючись на наступний сигнал. Резистор 120 Ом поглинає сигнал, запобігаючи відбиттю.

Без термінаторів: на малих швидкостях (<125 кбіт/с) система може працювати, але нестабільно. На швидкостях 500+ кбіт/с відбиття стають настільки серйозними, що шина повністю не функціонує.

Перевірка: мультиметр між CAN_H і CAN_L при вимкненому живленні — має показати ~60 Ом (два резистори по 120 паралельно). Якщо показує 120 — один резистор відсутній. Якщо нескінченність — обидва відсутні.

CAN FD (Flexible Data-rate, ISO 11898-1:2015) — розширення з двома ключовими покращеннями: більший payload (до 64 байт замість 8) та подвійний baud rate у фазі даних (до 8 Мбіт/с).

Фаза арбітраж залишається на класичній швидкості (до 1 Мбіт/с) для сумісності. Після арбітражу переможець переключається на вищу швидкість для передачі даних, потім повертається для ACK та EOF.

Вимоги: CAN FD трансивер (наприклад, TJA1044), контролер з підтримкою FD (STM32G0/G4/H7 — FDCAN), та відповідне програмне налаштування. Класичні CAN-вузли у мережі з CAN FD не зрозуміють FD-фреймів і генеруватимуть Error Frame.
